# Clark Air Swin2SR browser experiment

> **Semantic research home:** all current conclusions, decisions, study
> protocols, policies, and evidence navigation live in
> [`../swin2sr_super_resolution_1_58bit/`](../swin2sr_super_resolution_1_58bit/).
> This legacy directory remains the implementation and immutable run root
> because active writers and sealed receipts record its exact paths and hashes.

This experiment tests whether BackdropKit's
`Xenova/swin2SR-lightweight-x2-64` q4 model can become a substantially smaller
Clark-packed model without sacrificing the small UI labels that make the
upscaler useful.

This is the active product goal. Clark Quantize is used only as a library of
scientific methods and prior evidence; no Clark large-model objective is part
of this experiment. Swin2SR is not a proxy for a later LLM. It is the shipped
BackdropKit feature being optimized.

## Promotion contract

The current q4 Transformers.js model remains in production unless a candidate
passes every gate below on the exact held-out manifests:

1. hard-ternary output is statistically non-inferior to the shipped q4 model
   for ground-truth PSNR, edge PSNR, OCR accuracy, and worst-decile quality;
2. no language-script or real-UI stratum has a material regression;
3. paired confidence intervals are reported, and an apparent mean improvement
   is not accepted when its lower confidence bound crosses the registered
   non-inferiority margin;
4. the deployment ledger reports actual packed codes, scales, protected
   tensors, metadata, and total bytes—not only ideal trit entropy;
5. the complete image-to-image graph executes through BackdropKit's browser
   integration with WebGPU and WASM/CPU fallback, within the registered
   latency and peak-memory budgets.

The research target is an approximately 1.58-bit ternary trunk with
whole-artifact cost reported honestly. Quality improvement is welcome, but
“without quality loss” is not claimed until the full held-out comparison
passes.

## What the first PTQ sweep established

The sweep uses four real Clark product images and protects or quantizes
different model surfaces. Artifacts include packed codes, scales, and all
unquantized tensors rather than reporting theoretical weight bits alone.

| Policy | Artifact | UI PSNR | Edge PSNR | PSNR vs FP32 |
| --- | ---: | ---: | ---: | ---: |
| FP16 raw package | 2,221,903 B | 47.015 | 50.674 | 99.000 |
| Linear ternary g60 | 878,657 B | 34.477 | 37.926 | 37.292 |
| Trunk ternary g60 | 620,091 B | 31.626 | 35.532 | 33.735 |
| All ternary g60 | 549,272 B | 17.052 | 24.818 | 17.181 |
| Linear binary g60 | 819,063 B | 32.430 | 35.981 | 34.594 |

One-shot compression is therefore a size proof, not a quality solution.
Quantizing the image-facing convolutions is especially destructive.

## Model-specific QAT

`train_swin2sr_qat.py` implements the quality lane:

- full-precision Swin2SR teacher;
- preregistered ternary controls: groupwise MSE-optimal, groupwise absmean,
  and Meta ParetoQ's exact learnable row-wise SEQ grid;
- attention-first, MLP-second quantization schedule;
- high-precision convolutions, normalization, and position-bias MLPs frozen;
- output, edge, ground-truth, and intermediate-feature distillation;
- UI-edge-biased crops plus JPEG degradation from real product imagery;
- learned per-channel input redistribution on biased projections, folded into
  the final bias so it adds no inference operator.
- atomic checkpoints with exact RNG/data-order restoration and signal-safe
  interruption records;
- a pinned teacher revision and pre-launch run manifests containing source,
  data, environment, and checkpoint hashes.

The default remains `--quantizer optimal_mse`. The long AdamW control was
launched with that default and was not relabeled after the fact. New matched
arms can use:

```bash
# BitNet-style groupwise absmean control.
python3 experiments/browser_swin2sr/train_swin2sr_qat.py \
  --quantizer absmean ...

# Exact ParetoQ ternary SEQ control: learnable per-row alpha and
# {-2 alpha / 3, 0, +2 alpha / 3} forward levels.
python3 experiments/browser_swin2sr/train_swin2sr_qat.py \
  --quantizer paretoq_seq ...

# Function-preserving block-Hadamard shaping before groupwise quantization.
python3 experiments/browser_swin2sr/train_swin2sr_qat.py \
  --rotation hadamard --rotation-block 4 ...
```

The SEQ implementation follows the authors'
[paper](https://arxiv.org/abs/2502.02631) and
[reference code](https://github.com/facebookresearch/ParetoQ). A one-step CPU
smoke verified 144 trainable scale tensors, a hard forward, checkpoint export,
and finite scale gradients. It is an ablation candidate, not a quality result.

Optimizer comparisons are explicit and checkpointed:

```bash
--optimizer adamw
--optimizer adamw_prox
--optimizer bonsai_qat8
--optimizer bonsai_qat8_muon
--optimizer bonsai_muon
--optimizer bonsai_muon_fast
--optimizer mirror_sgd
--optimizer mirror_sgd_adagrad
--optimizer factored_adafactor
```

The completed long-run evidence remains the untouched `adamw` control.
`adamw_prox` adds only the historical Sana proximal schedule; `bonsai_qat8`
uses an int8 first moment and factored second moment; the final arm additionally
enables periodic Muon. The two direct Muon arms compare the original
per-matrix implementation with the later same-shape batched implementation.
The mirror arms compare stateless group-normalized updates with group AdaGrad,
and factored Adafactor carries only row/column second moments for 2D masters.
Use `--reset-optimizer` only for a preregistered matched branch from a shared
model checkpoint. Ordinary resume rejects optimizer switches.

Wall-clock time is recorded but never used as a quality tie-breaker because
concurrent MPS scheduling makes it non-comparable.

### Winner-only recovery protocol

Aggregate quality can hide a product regression. At 2,000 steps, the first
promising arm improved aggregate ground-truth PSNR while still trailing q4 on
held-out RICO screens. `rank_factorial_source_aware.py` therefore reranks each
stage by its weakest held-out source before a recovery base is chosen.

Local layer error was also rejected as a precision-island selector. On a
source-balanced 100-image output probe, restoring the largest-error trained
masters in the leading hard-ternary model made RICO and teacher fidelity worse.
The ternary network had co-adapted; splicing masters back into it did not
recover the function. `evaluate_restoration_islands.py` preserves this negative
result so recovery focuses on trained function-level compensation.

`run_recovery_factorial.py` preregisters 24 winner-only arms:

- group size 60 or 30;
- ordinary ternary levels or a two-scalar-per-matrix correction (576 bytes);
- frozen, normalization-only, or normalization-plus-residual compensation;
- balanced or teacher-heavy function-local distillation.

Recovery uses `backdropkit-product-source-language-v2`: 35% RICO, 15% Aria,
20% WebSight, 20% FLORES, and 10% public-domain natural images. The FLORES
share is divided equally across all 204 language-script variants. A resumed
checkpoint must match the complete sampler metadata or fail closed.

The matched 20-step calibration in `recovery-lr-pilot-receipt.json` selected
`1e-6` over `5e-6`. On the same 100 held-out samples, `1e-6` limited the
ground-truth change versus its base to -0.0657 dB, kept RICO within -0.0060 dB,
and improved teacher fidelity by +0.1967 dB. The `5e-6` arm lost -0.2317 dB
and reduced teacher fidelity. This is a learning-rate decision only, not
promotion evidence.

`launch_recovery_after_stage3.sh` waits for all 5,000-step finalists, selects
the source-aware winner, and runs only the first 500-step recovery stage. It
does not chain later stages without reviewing the held-out evidence.

The long AdamW control was stopped signal-safely at step 16,572 after its best
checkpoint (step 13,750) failed the exact q4 product gate. On the first 200
sealed real-UI samples it trailed q4 by 0.7017 dB ground-truth PSNR (paired
bootstrap 95% CI `[-0.8716,-0.5324]`) and 0.5912 dB edge PSNR (95% CI
`[-0.7473,-0.4273]`), winning only 18.5% and 21.0% of samples. The interruption
checkpoint and `q4-first200-comparison.json` are preserved; continuing that
plateau would spend compute without reaching the registered -0.10/-0.15 dB
margins.

The Hadamard control rotates each selected linear input and its weight columns
in the same orthonormal basis. Tests prove the unquantized function is
unchanged, hard rotated checkpoints export to an equivalent ordinary dense
state, and checkpoints preserve rotation metadata. Rotated packed artifacts
retain weights in the shaped basis and declare the required input transform;
they must be exported from one canonical source-device materialization, not
from a backend-local reprojection of the continuous checkpoint. The
materialization produces both a plain dense evaluation state and a
rotation-preserving runtime state, hashes both, and makes them one model
identity for packed, ONNX, WebGPU, WASM, and CPU paths.

The redistribution follows the inference-agnostic idea in
[QuantSR](https://github.com/htqin/QuantSR). The progressive, localized
distillation direction is consistent with
[QuantSR+](https://arxiv.org/abs/2605.22351). PrismML's public
[Bonsai demo and whitepapers](https://github.com/PrismML-Eng/Bonsai-demo)
establish practical groupwise binary/ternary formats and native packed kernels,
but do not publish the proprietary model-conversion training method.

The exporter verifies the materialization and recovers its exact hard
codes/scales; it never quantizes the dense hard state a second time. Every new
export includes a `storage_ledger` that separates mathematical code
entropy from actual deployment cost. A verified export of the prior 3,000-step
hard state contained:

| Quantity | Measured value |
| --- | ---: |
| Ideal ternary entropy | 1.58496 bits / selected weight |
| Base-3 packed codes | 1.60000 bits / selected weight |
| FP16 group-scale overhead | 0.26667 bits / selected weight |
| Packed selected trunk | 1.86667 bits / selected weight |
| Selected parameter fraction | 68.7523% |
| Whole model data | 6.28301 bits / model parameter |

The gap is mostly the deliberately protected FP16 convolutional and
image-facing surfaces. This is why the project reports both a ternary trunk
and whole-model effective bits instead of describing the entire artifact as
"1.58-bit."

`model_surface_ledger.py` now accounts for every one of the model's 1,005,348
parameters. The current core covers 691,200 values (68.75%). A full
matrix-and-convolution treatment covers 977,604 values (97.24%); with
base-3 packing, FP16 group scales at group size 240, FP16 normalization
weights, and int8 biases/other parameters, the projected tensor payload is
234,572 bytes or 1.8666 whole-model bits per parameter. This is the honest
deployable target corresponding to an approximately 1.58-bit ternary weight
model; achieving 1.58 bits for the entire file would require hiding scales and
non-weight parameters.

`surface_schedule.py` pins the quality-preserving expansion order. Attention
and MLP projections enter first, residual-body convolutions ramp from 25–55%,
position-bias MLPs from 50–72%, and the ingress/reconstruction convolutions
only from 70–92%. This prevents the full-surface target from becoming a
one-shot PTQ experiment: the optimizer winner is first established on the
current core, then promoted through increasingly image-sensitive surfaces.

The decisive full-surface experiment has two matched initializations. One
starts directly from the pinned, non-quantized `caidas/swin2SR-lightweight-x2-64`
teacher and progressively ternarizes all 204 registered surfaces. The other
starts from the best recovered hard-ternary core and progressively adds the
remaining surfaces. Both lanes use the same seed, product-balanced sample
order, augmentations, schedule, loss, optimizer, and held-out bundle. A new
full-surface phase always starts its sample stream at zero; only a
full-surface checkpoint may restore its exact cursor. This keeps the recovered
lane from receiving extra data and makes fresh FP32 the unbiased control,
rather than treating the shipped q4 artifact as a training source.

`verify_browser_artifact.py` decodes the actual binary, reconstructs every raw
and packed tensor, applies any declared inverse shaping, and compares the full
Swin2SR output with its source checkpoint. The rotation smoke passed the
registered numerical gate with `68.9023 dB` output PSNR, mean absolute error
`0.0002687`, and maximum error `0.0030566` (below one 8-bit intensity level).

## Browser runtime proof

`runtime/` contains the minimum deployment primitive:

- 20 base-3 weights per `uint32` (1.6 payload bits per trit);
- batched WebGPU WGSL packed ternary matrix execution;
- Rust/WASM scalar fallback for browsers without WebGPU;
- a strict native Rust loader for `model.json`/`model.bin`;
- a three-vector fixture taken from a real 60x60 Swin2SR attention projection.

The kernel streams base-3 words sequentially, including unaligned row, word,
and scale boundaries. Native tests reject invalid metadata without invoking a
browser-only error path. On 2026-07-29, the optimized web build passed the same
real batched fixture in an in-app Chromium runtime through both paths:

- WebGPU: maximum absolute error `2.980232238769531e-7`;
- forced WASM: maximum absolute error `2.384185791015625e-7`.

The WebGPU device and compiled pipeline are cached and reset on device loss;
temporary input/output buffers are destroyed after each call. On the same
small fixture, the second invocation took `1.2 ms` on WebGPU and `0.1 ms` on
WASM, compared with `3.6 ms` and `1.2 ms` cold. These figures prove the cache
path, but are not representative whole-model latency benchmarks.

The native loader rejects inconsistent shapes, padding, payload sizes, dtypes,
and out-of-bounds byte ranges. Its release-mode conformance executable loaded
the existing 771 KB packed artifact and matched an independent NumPy decode at
`2.384185791015625e-7` maximum and `3.62491441308066e-8` mean absolute error.
The library cross-checks for ARM64/x86-64 macOS, ARM64/x86-64 Windows,
ARM64/x86-64 Linux musl, and `wasm32-unknown-unknown`; only ARM64 macOS and
WASM/WebGPU have execution receipts on this machine.

The runtime now also has tested scalar/WASM kernels for same-padded
convolution, exact-ERF GELU, LayerNorm, stable softmax, PyTorch-order
PixelShuffle, shifted window partition/reversal, shifted-window mask creation,
relative-position bias, and Swin2SR cosine attention. `model.rs` wires those
operators into a complete, independent x2 Swin2SR graph that reads both raw
FP16 and base-3 tensors from the Clark artifact.

On the 64x64 to 128x128 conformance fixture, the release ARM64 runner completed
in 1.99 seconds with `0.0004800` maximum error and the browser WASM runner
completed in 4.09 seconds with `0.0004801` maximum error against the PyTorch
hard state. The browser loaded the 872,153-byte core model plus 142,001-byte
WASM runtime without ONNX Runtime. The maximum error is below one 8-bit
intensity level.

The artifact loader also enforces the declared block-Hadamard input transform
only on packed linear tensors. An actual
`absmean__hadamard__bonsai_qat8_muon` checkpoint completed the same full native
64x64 pass in 2.02 seconds with `0.0003555` maximum error, so a rotated
factorial winner can be deployed without converting it back to the
quality-losing unrotated basis.

Routing packed linear layers directly through row-streaming ternary matmul
reduced unrotated native latency from 2.57 to 1.99 seconds, rotated native
latency from 3.56 to 2.02 seconds, and browser WASM latency from 5.29 to 4.09
seconds without changing output. It also avoids materializing full dense
copies of selected linear weights.

This proves a genuinely cross-browser inference engine, but it is still the
correctness implementation: it decodes selected tensors to dense f32 and uses
scalar graph operators. Production work remains to route linear layers through
the packed WebGPU/WASM kernels, add WebGPU convolution/non-linear kernels,
reuse tensor allocations through a memory arena, and measure the final
97.24%-ternary artifact on every registered browser surface.

The full-surface artifact path is now exercised independently of candidate
quality. An `absmean`/Hadamard smoke packs 204 tensors and 977,604 weights into
a 378,705-byte model package (2.2583 whole-model data bits per parameter).
Hadamard transforms are tensor-local on exactly the 144 core projections; the
48 position-bias matrices and 12 convolutions remain in their native input
bases. The package passes Python graph conformance at 90.30 dB against its hard
state, native ARM64 scalar conformance in 2.21 seconds, and Chromium WASM
conformance in 4.99 seconds with `0.0001056` maximum error. The receipt is
`full-surface-runtime-smoke-receipt.json`.

This smoke also closed three exporter correctness gaps before the quality
winner exists: group-padding trits are no longer serialized as weights,
`absmean` codes/scales are packed from the master exactly once, and per-tensor
input transforms prevent non-core surfaces from receiving Hadamard shaping.
It is an infrastructure receipt only, not promotion evidence.

### Portable ONNX bridge

ONNX Runtime Web lists `MatMulNBits` on WebGPU, but its supported optimized
quantization format is currently 4-bit rather than 2-bit or ternary. The
[official quantization guide](https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html#quantize-to-int4uint4)
documents Int4/UInt4, and ONNX's open
[low-bit format discussion](https://github.com/onnx/onnx/issues/7691)
explicitly records the lack of 2-bit and lookup-table quantization.

`onnx_packed_bridge.py` therefore proves a no-custom-operator fallback. It
stores five trits in each `uint8`, decodes them through a 243x5 constant lookup
table, expands regular FP16 group scales, and feeds an ordinary ONNX `MatMul`.
All operators are part of the
[ONNX Runtime WebGPU support table](https://github.com/microsoft/onnxruntime/blob/main/js/web/docs/webgpu-operators.md).

The real Swin-shaped 120-to-60 projection receipt is:

| Quantity | Measured value |
| --- | ---: |
| Packed codes | 1,440 B |
| FP16 group scales | 240 B |
| Codes plus scales | 1.86667 bits / weight |
| Complete ONNX test graph | 8,099 B |
| WebGPU maximum error | `2.384185791015625e-7` |
| WASM maximum error | `2.384185791015625e-7` |
| WebGPU warm median | 1.4 ms |
| WASM warm median | below the 0.1 ms timer resolution |

This bridge makes correctness and cross-browser loading independent of a
custom ORT build. It is not yet the full model and it reconstructs dense
weights at session initialization, so it does not replace the native packed
kernel for steady-state speed or memory. The intended order is: use this graph
rewrite to establish end-to-end portability, then replace reconstruction plus
`MatMul` with the already proven WebGPU/WASM packed primitive behind the same
artifact contract.

`build_portable_onnx_artifact.py` extends the same rewrite to the complete
Transformers.js Swin2SR graph. It maps all 484 PyTorch state tensors to the
pinned ONNX export by exact teacher bytes, preserves the export-time transpose
of every linear weight, and rejects any initializer that is missing,
ambiguous, or not already hard ternary. A core-scope smoke rewrote 144 tensors
and ran a complete 64x64 to 128x128 reconstruction in Chromium:

| Backend | Session | Inference runs | Maximum error vs PyTorch |
| --- | ---: | --- | ---: |
| WebGPU | 4.37 s | 1036.2, 74.4, 46.6 ms | `0.00022890` |
| WASM | 5.84 s | 449.6, 448.8, 486.8 ms | `0.00022908` |

The error is below one 8-bit intensity level and comes from the deployed FP16
group scales. The core-only file is 5,725,534 bytes—50,445 bytes larger than
the shipped q4 ONNX—because the legacy 19,113-node graph and protected dense
weights dominate its payload. This is a portability proof, not the size
winner. The 97.24%-ternary scope should remove more dense payload; the compact
~235 KB target still requires the dedicated graph runner.

The portable builder accepts only a canonical materialization manifest and
preserves a Hadamard-trained basis. It verifies the runtime-state hash, inserts
a shared 4x4 normalized Hadamard transform
before each of the 144 selected ONNX `MatMul` inputs, then packs the rotated
weights rather than silently expanding them back into a non-ternary basis. An
actual rotated stage-one arm ran end to end at 29.9–31.5 ms warm on Chromium
WebGPU and 371.5–381.6 ms on Chromium WASM, with maximum errors of
`0.0002098` and `0.0002097`. This keeps both browser backends viable if the
held-out winner is rotated.

The canonical step-14,000 infrastructure artifact validates the complete
identity chain over all 204 targeted surfaces. Its deterministic gzip ONNX
package is 677,510 bytes. The same package passed in Chromium at 37.5–59.1 ms
warm on WebGPU and 490.1–505.4 ms warm on WASM, with maximum error
`0.0003047` against the canonical dense hard state. This is runtime and
packaging evidence for an intermediate checkpoint, not visual-quality or
promotion evidence.
